# SQL 风险审查报告（输出模板）

> 这是 odps-sql-review 的标准输出模板。无论 AI Agent 还是 Python CLI，
> 最终生成的报告都必须按这个结构输出，便于评审人快速扫描。
>
> 模板原则：
> - 永远输出风险等级；
> - 永远输出 “需要确认项”；
> - 不允许只回答 "looks good"。

```markdown
# SQL 风险审查报告

## 0. 总体结论
- 总风险等级：高 / 中 / 低
- 是否建议直接上线：是 / 否
- 主要阻塞点：
  - <列出 high + blocking 的问题>
- 主要性能瓶颈：
  - <列出 performance 类目的关键问题>
- 需要确认项：
  - <列出表粒度 / 唯一键 / 表大小 / LogView 等>

## 1. 高风险问题
### 风险点标题
- 风险点：<简述>
- 证据 SQL 片段：```sql ... ```
- 为什么危险：<原因>
- 建议修改方式：<可操作的改写建议>
- 是否阻塞上线：是 / 否

## 2. 中风险问题
### 风险点标题
- 风险点：<简述>
- 证据 SQL 片段：```sql ... ```
- 影响：<对资源 / 口径 / 报表的影响>
- 建议修改方式：<可操作的改写建议>

## 3. 低风险 / 可读性问题
- SELECT *
- 单字母别名
- 重复 CASE WHEN
- 缺少注释
- 过长 CTE
- 命名不清

## 4. 性能优化建议
分组输出（缺项时直接写 “暂无明显问题”）：
- 分区裁剪
- Join 优化
- Group By / Count Distinct 优化
- 年活 / 月活 / 长周期去重优化
- 动态分区优化
- Reducer / Joiner / 并行度建议
- 中间表 / 滚动表建议

> 不要盲目给固定 ODPS SET 参数；缺少 LogView / 数据量 / 资源配额时，
> 标注 “需要结合 LogView / 数据量确认”。

## 5. 指标口径解释
按指标列出：
- 指标名称
- 分子
- 分母
- 过滤条件
- GROUP BY 粒度
- 是否存在重复计算风险
- 是否需要业务确认

## 6. 建议改写 SQL
- 给出可执行的改写片段；
- 若唯一键 / 表粒度 / 字段含义未知，不要强行改写；
- 用 “候选改写方向” 替代具体 SQL。

## 7. 上线前验数 SQL
至少包含：
- 源分区行数检查
- 目标行数检查
- 主键重复检查
- 核心字段空值检查
- JOIN 前后行数对比
- 昨天 / 今天指标波动对比
- 分区数据量检查
- COUNT DISTINCT 校验
- 右表关联键唯一性检查

## 8. 需要我补充的信息
仅列出影响判断的项目：
- 表的分区列；
- 表粒度；
- 唯一键；
- 表大小级别；
- fact / dim 标识；
- 是否允许近似去重；
- 目标表主键；
- 是否调度任务；
- LogView 数据。
```
