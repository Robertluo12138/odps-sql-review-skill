# 报告输出模板（output_template）

> 这是 odps-sql-review skill 的 **唯一权威输出格式**。
> AI Agent 在生成评审报告时必须严格按这个 8 个章节的结构输出，
> 章节标题、章节编号、字段名都要保持一致，便于评审同事快速扫描。
>
> 即使没有发现任何风险，也必须输出全部章节，缺项写
> “暂无 / 暂未发现 ... ，仍需结合 LogView / 数据量复核”，
> 不要直接输出 “looks good”。

---

## 章节硬性约束

- 章节编号 0-8 不能跳过；
- 即使没有风险也必须输出 “暂未发现 ...” 占位文本；
- 第 0 节的 4 个字段（风险等级、是否上线、阻塞点、性能瓶颈、确认项）
  顺序固定；
- 第 4 节的 7 个子小节顺序固定，分别是：
  分区裁剪、Join 优化、Group By/Count Distinct 优化、
  年活/月活/长周期去重优化、动态分区优化、Reducer/Joiner/并行度建议、
  中间表/滚动表建议；
- 第 7 节按 V1-V9 顺序输出；
- 报告结尾建议加一句免责声明：
  > 本报告基于静态分析与业务上下文，未连接 ODPS。最终风险结论需要
  > 结合数据量、LogView、业务口径、调度上下文复核。
